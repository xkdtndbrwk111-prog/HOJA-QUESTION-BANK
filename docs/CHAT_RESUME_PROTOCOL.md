# HOJA QB — 대화 중단 복구 프로토콜 (v1)

## 목적
긴 파일·코드·검수 출력 때문에 ChatGPT 대화가 조기 종료되어도, **마지막으로 GitHub에 저장되어 검증된 작업 상태**부터 다시 시작한다. 채팅 자체는 영구 저장소가 아니다.

## 새 대화에서 입력할 명령
> HOJA 문제은행 이어서. `xkdtndbrwk111-prog/HOJA-QUESTION-BANK` GitHub main의 `AGENTS.md`, `CURRENT_WORK.md`, `workflow/state.json`을 읽고 최신 SHA와 실제 근거 파일을 확인해. 검증 스크립트가 있으면 실행하고 마지막 저장 체크포인트부터 이어가. 미완료/승인/배포를 구분하고 정본은 보호해.

## 매 작업 시작·종료 절차
1. **읽기:** GitHub main의 최신 커밋, 위 3개 진입 문서, 작업 대상의 실제 파일, 정본 색인, 렌더러 버전을 확인한다.
2. **작업:** 정본 불변. 새 실험 버전/임시 브랜치를 사용한다. 문항 의미 태그 → 기존 렌더러 표시 → 검수기 QA → 교사 승인 → GitHub 정본 등록 → 게임 배포는 서로 다른 단계.
3. **검증:** 데이터 스키마·정답 참조·원본 SHA·실제 브라우저 검증 여부를 나눠 쓴다. '0 오류'는 검사를 **실제로 수행한 조건**에 한해 적는다.
4. **체크포인트:** 성공한 파일 경로, 커밋, 결과, 실패/미확인 항목, 다음 행동을 state와 CURRENT_WORK에 기록해 **같은 커밋**에 올린다. 코드 변경과 인수인계 갱신을 분리하지 않는다.
5. **복원:** 새 채팅은 이미 완료된 작업을 다시 개발하지 않는다. 최신 main에서 존재·SHA·내용이 확인된 부분만 완료로 간주한다.

## 필수 용어
- **문항 정본 승인:** 교사의 콘텐츠 승인. ZIP 내부 `release/approval.json` 또는 승인 manifest 등 실제 증빙이 필요.
- **GitHub 정본 등록:** 원격 `approved/`에 **정본 파일이 실제 존재하고 해시가 일치**해야 완료.
- **렌더러:** A/C/D, auto split/stack, 그림·수식·선택지·주관식 흐름을 실제 화면처럼 재현하는 표시 엔진.
- **검수기:** 정답·그림·보기·overflow·상태·메모를 검토/기록하는 QA UI 및 자동 정적 점검. 검수기 PASS≠교사의 교육적 내용 승인.
- **운영 배포:** 실제 게임 로더/점수/학생 세션에 적용된 상태. 앞선 단계 완료와 자동 연동되지 않음.

## 주기·한계
- 새 실험 파일, 검수 범위, 승인 단계, 원격 파일 등록, GitHub 배포 상태가 바뀔 때마다 체크포인트를 **함께 갱신**한다.
- 실제 대화가 갑자기 잘리면 마지막 커밋 이후의 미저장 작업은 복구할 수 없다.
- 이 절차는 자동 백그라운드 저장, ChatGPT 자동 새 대화 생성, 문항 자동 승인 기능을 제공하지 않는다.
