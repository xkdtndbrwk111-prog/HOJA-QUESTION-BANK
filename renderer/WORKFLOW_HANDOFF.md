# HOJA 렌더러 · 운영 인수인계 / 대화 중단 복구 문서

**최종 갱신:** 2026-11-22 (KST)
**이 문서가 하는 일:** 다음 채팅, 다른 AI/개발자 또는 시간이 지난 뒤에도 '지금 어느 버전이 기준이고 무엇이 미완료인지'를 복원한다. 매번 작업 시작 시 이 문서를 먼저 읽고 GitHub의 실제 파일과 대조한다.

| **최신 YBM 실험 화면** | [v0.5 HTML](experiments/2026-11-22/ybm-183-tagged-v0.5.html) | 영어 5·6학년 YBM 183문항 **승인 전 후보** |

## 2. 한 번에 화면 열기

1. GitHub에서 [실험 HTML](experiments/2026-11-22/ybm-183-tagged-v0.5.html)을 열고 **Download raw file**로 저장한다. 또는 저장소를 clone한 후 HTML을 브라우저에서 연다.
2. 오른쪽 검토 화면, 왼쪽 단원/문항/해상도 메뉴를 사용한다. \`5학년 10~12단원\` 92문항, \`6학년 10~12단원\` 91문항.
3. A/C/D 유형·좌우/상하/자동 배치를 비교한다. 새 문제로 이동하면 자동 배치로 복귀한다.
4. 태그 패널의 필터(대화·읽기·정보 그림 등)로 문항을 빠르게 점검한다.
5. 객관식은 실제 4보기에서 3개를 화면에 보여 주는 검토 모드다. 주관식은 **큰 정답 공개 → 교사의 정답/오답 판정 → 다음 문제**를 확인한다. 검토 UI는 실제 점수를 계산하지 않는다.

HTML 안에는 문항·삽화·렌더링 태그가 함께 들어 있어 **인터넷 없이 단독으로 열 수 있다.** GitHub의 \`blob\` 페이지 자체가 HTML 실행 화면은 아니며 다운로드 후 로컬로 연다.

## 3. 2026-11-22 합의된 화면 규칙

- **대화 발화는 무조건 위→아래.** 대화문 전체는 하나의 패널, 개별 발화에 별도 테두리/박스 없음.
- 인물명은 **같은 문항에서 서로 다른 밝은 색**, 동일 인물은 같은 색. 대사 자체는 흰색.
- 가장 긴 화자 이름의 실제 폭을 측정하여 **대사 시작 열 정렬**. 극단적으로 긴 이름은 줄바꿈.
- **대화 전체 묶음을 패널 세로 중앙**에 배치. 여러 발화를 흩뿌려 세로 공간을 채우지 않는다.
- **짧은 단문·빈칸 지문은 남는 면적을 이용해 글자 크기를 확대.** v0.5는 기존 글자 맞춤 이후 패널의 실제 경계를 검사하여 허용 범위에서 글자를 추가 확대한다. 글자·선택지가 겹치면 확대를 되돌린다.
- 정밀 그림(지도·길찾기·수학 도형·그래프·과학 도표)은 일반 상황 삽화보다 공간을 더 확보. 대화+정보 그림은 **둘 다 살려야 한다.**
- 질문/지문/보기의 중요도를 따로 판단하고, 기본 가독성을 통과한 후보 사이에서 마지막에 용적률을 비교한다. **전체 용적률 자동 점수 및 최적 배치 탐색은 아직 미구현**이다.

태그 표준은 [tags/README.md](tags/README.md), 실험별 변경 내역은 [experiments/2026-11-22/README.md](experiments/2026-11-22/README.md) 참조.

## 4. 확인된 검사 및 문제

- YBM **183문항 × HD(1280×720)·FHD(1920×1080)**를 v0.4와 v0.5에서 동일하게 자동 점검.
- 데이터 불변 (문항 JSON 문자열의 SHA-256 일치), JS 실행 오류 없음, v0.5 때문에 새로 추가된 넘침 의심 문항 없음.
- 기존 자동 경고: **HD 24 / FHD 63문항**, v0.4와 동일. 렌더러의 텍스트 높이 라운딩 등에 따른 오탐 가능성이 있지만 모두 정상이라고 단정하지 않는다. **전체 교사 시각 검수는 미완료**.
- 대화 문항에서 상·하 여백의 불균형을 v0.5에서 개선 (검사한 다중 발화 장면에서 차이 0). 기본 문자 폰트 확대는 HD 173문항, FHD 176문항에서 양수.
- 실제 화면 예: 5학년 10단원 Q08(짧은 빈칸), Q09(2명 대화), 5학년 11단원 Q34(대화+정보 삽화). 일반 지도·장문·그림 선택지 회귀는 향후 검수 지속.
- 4K 대표 화면은 시험했으나 **v0.5 전체 183문항의 4K 전수 검사까지 완료했다고 주장하지 않는다.**

## 5. 다시 작업을 시작할 때

\`\`\`bash
git clone https://github.com/xkdtndbrwk111-prog/HOJA-QUESTION-BANK.git
cd HOJA-QUESTION-BANK
python -m http.server 8000
# 브라우저에서
# http://localhost:8000/renderer/experiments/2026-11-22/ybm-183-tagged-v0.5.html
\`\`\`

- 이미 완성된 전체 HTML은 [실험 보존본](experiments/2026-11-22/ybm-183-tagged-v0.5.html)에 있다. 승인 원본 ZIP을 가져와 재생성할 필요는 없다.
- 생성·수정 경위를 더 살펴보려면 [v0.4→v0.5 패치](experiments/2026-11-22/patch_hoja_stimulus_v05.py)와 [전체 회귀 검사 소스](experiments/2026-11-22/qa_hoja_v05_full.py)를 참조한다. 두 파일에 있는 \`/mnt/data\` 경로는 **이전 실험 환경 전용**이므로 로컬 경로에 맞춰 수정해야 한다.
- 태그를 새 문항에 붙이려면 [참고 자동 분류기](tags/auto-classifier-v0.1.js)를 사용할 수 있다. 최초 183문항 배치 태그를 만들던 [Python 원본 소스](tags/build_hoja_tag_trial_original.py)는 별도 후보 ZIP 및 이미지가 필요하다. **그 입력 자료들은 현재 저장소의 일부가 아니다.** 따라서 소스만으로 초기 태깅 전체를 즉시 재생성할 수 있다고 말하면 안 된다.
- 교과서·교사 승인이 필요한 콘텐츠와 미디어는 라이선스/재배포 가능 여부 확인 후 공개 처리한다.

## 6. 앞으로 **수정하는 날마다 함께 갱신할 것**

수정 사항이 있는 턴에서 코드·문서·검사 보고서를 **같은 작업의 일부로 동기화**한다. 채팅 기록만을 변경 로그로 사용하지 않는다.

1. 새 버전은 \`renderer/experiments/YYYY-MM-DD/...\`에 **추가 저장**한다. 기존 HTML과 승인 ZIP은 덮어쓰지 않는다.
2. 태그 스키마나 자동 분류 논리가 변하면 \`renderer/tags/\`의 스키마·분류기·예시·태그 JSON을 같이 수정한다.
3. **이 문서**, [실험 README](experiments/2026-11-22/README.md), [CHANGELOG.md](CHANGELOG.md), 필요 시 [VERSION.json](VERSION.json) 을 갱신한다. 특히 \`VERSION.json\`의 current는 교사 승인 없이 변경하지 않는다.
4. 회귀 검사 결과(검사 문항 수, 해상도, 기존 경고, 새 경고, 주관식 흐름, 원본 데이터 무결성)를 기록한다. 0건이라는 주장은 실제로 재검증한 조건에만 붙인다.
5. 다음 담당자에게 **마지막 파일 경로, 완료 상태, 미해결 문제, 다음 작업**을 명시한다. '배포 완료'와 '오프라인 검토판 보관'을 구별한다.

**중요:** 이 체크리스트는 작업 시 지켜야 하는 관리 규칙이다. GitHub에서 다른 사람이 변경한 것을 ChatGPT가 대화와 무관하게 24시간 자동 추적/갱신하는 기능이 설정된 것은 아니다.
